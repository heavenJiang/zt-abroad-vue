# zt-abroad-vue 前端开发规范

> 适用范围：zt-abroad-vue（留学智能体平台管理后台，RuoYi-Vue3 3.9.2 二次开发：Vue 3 + Vite 6 + Element Plus 2 + Pinia）。
> 沿用 zt-vue 的前端规范（从现有代码、后端代码生成器模板 zt-generator `vm/vue/v3`、`vm/js/api.js.vm` 与后端《开发规范》归纳），示例改为留学业务。新增、修改页面均须遵守。
> 页面清单与验收标准见后端工程 `doc/研发/04-模块拆分.md`。
> 版本：v1.0（2026-10-13）

## 1 目录与命名

| 对象 | 位置 | 命名 |
| --- | --- | --- |
| 业务页面 | `src/views/<模块>/<资源>/index.vue` | 模块、资源与后端路径一致：`/abroad/program` → `src/views/abroad/program/index.vue`；菜单 component 字段即 `abroad/program/index` |
| 页面私有子组件 | 与 index.vue 同目录 | 小驼峰文件名，如 `followDialog.vue`、`assignDialog.vue`（同 `system/user/authRole.vue`、`tool/gen/genInfoForm.vue`） |
| 模块内共用组件 | `src/views/<模块>/components/` | 大驼峰文件名，如 `TierTag.vue`（冲稳保标签） |
| 全局通用组件 | `src/components/<组件名>/index.vue` | 大驼峰目录名；只放与业务无关的组件 |
| 接口 | `src/api/<模块>/<资源>.js` | 一个后端控制器一个文件 |
| 工具函数 | `src/utils/` | 已有 `zt.js`（parseTime、resetForm、addDateRange…）、`validate.js`、`dict.js`，先复用再新增 |

## 2 接口层（src/api）

1. 只用 `import request from '@/utils/request'`，每个接口一个具名导出函数，函数上一行写中文注释（`// 查询院校列表`）。
2. 函数命名：列表 `listXxx(query)`、详情 `getXxx(id)`、新增 `addXxx(data)`、修改 `updateXxx(data)`、删除 `delXxx(ids)`；专用接口用动词 + 资源，如 `assignLead`、`publishReport`、`recalcAssessment`。
3. GET 参数放 `params`，POST/PUT 请求体放 `data`；URL 以 `/` 开头、拼接 `+ id`，与生成器模板一致；文件单引号、无分号、两空格缩进。
4. 导出不写在 api 文件中，页面里用 `proxy.download('abroad/xxx/export', {...queryParams}, 'xxx_时间戳.xlsx')`。
5. 上传需要读取失败明细时，用 `el-upload`（`action`、`headers: { Authorization: 'Bearer ' + getToken() }`、`data`）直接提交，在 `on-success` 中读取响应（axios 拦截器对 `code != 200` 会弹错并丢弃响应体），同 `system/user` 的导入。

## 3 页面结构

1. 单文件组件顺序：`<template>`、`<script setup name="资源大驼峰">`、`<style scoped>`（需要时）。`name` 与路由名一致（如 `Program`），供 keep-alive 缓存。
2. 只用组合式 API 与 `<script setup>`；`ref`、`reactive`、`toRefs`、`computed`、`watch`、`getCurrentInstance`、`useDict` 由 unplugin-auto-import 自动导入，不手写 import。
3. 列表页骨架（与生成器一致）：搜索表单 `queryRef`（`v-show="showSearch"`、`:inline="true"`）→ 工具栏 `el-row :gutter="10" class="mb8"`（新增、修改、删除、导出 + `right-toolbar`）→ `el-table v-loading` → `pagination` → 表单弹窗 `el-dialog append-to-body`。
4. 状态统一放 `const data = reactive({ form, queryParams, rules })` 再 `toRefs`；列表、弹窗开关、loading、ids、single、multiple、total、title 用 `ref`。
5. 方法命名沿用生成器：`getList`、`cancel`、`reset`、`handleQuery`、`resetQuery`、`handleSelectionChange`、`handleAdd`、`handleUpdate`、`submitForm`、`handleDelete`、`handleExport`；每个方法上一行 `/** 中文说明 */`。
6. 多页签页面用 `el-tabs`，每个页签内容较多时拆成同目录子组件。
7. 详情用 `el-drawer` 或只读 `el-descriptions`；大段文本（AI 生成内容、原始资料）用 `<pre>` 等宽显示。

## 4 代码风格

1. 两空格缩进；脚本不写分号；脚本字符串用双引号（生成器风格），模板属性用双引号。
2. 模板组件名用短横线（`el-table-column`、`dict-tag`、`right-toolbar`）。
3. 不引入新的第三方依赖；确需引入须评审并写入 `package.json` 固定版本。
4. 不使用 `any` 类的全局变量；跨页面共享状态放 `src/store/modules`（Pinia）。
5. 不在前端硬编码后端可配置的枚举：一律用字典（第 5 节）。

## 5 字典、权限、提示

| 场景 | 写法 |
| --- | --- |
| 字典 | `const { abr_country, sys_normal_disable } = useDict("abr_country", "sys_normal_disable")`；列表用 `<dict-tag :options="abr_country" :value="row.x" />`；下拉、单选按 `dict.value`/`dict.label` 循环 |
| 按钮权限 | 指令 `v-hasPermi="['abroad:lead:edit']"`；脚本里判断用 `proxy.$auth.hasPermi(...)` |
| 成功、失败提示 | `proxy.$modal.msgSuccess` / `msgError` / `msgWarning`；后端失败信息由 request 拦截器统一弹出，页面不重复提示 |
| 二次确认 | `proxy.$modal.confirm('…').then(() => …).then(() => …).catch(() => {})` |
| 后端返回附加提示 | 写操作成功后若 `response.msg` 不是“操作成功”，用 `proxy.$modal.alertWarning(response.msg)` 显示（如“报告已生成，待顾问审核”） |
| 时间 | 列表 `parseTime(row.x)`（yyyy-MM-dd HH:mm:ss）；日期范围 `el-date-picker type="daterange|datetimerange"`，`value-format` 与后端一致，参数放 `queryParams.params.beginTime/endTime` 或用 `proxy.addDateRange` |

## 6 表单与字段

1. 必填项在 `rules` 中加 `required`，提示“xxx不能为空”；与后端校验规则保持一致（编码正则、长度、范围），前端校验只做友好提示，以后端为准。
2. 编码类字段（xxxCode、apiVersion、appKey 等）新增时可填、修改时 `:disabled="form.xxxId != undefined"`。
3. 数字用 `el-input-number`（`controls-position="right"`、`:min`、`:max`、金额 `:precision="4"`）。
4. 个人信息（学生手机号、微信号、证件号、成绩单）：列表默认脱敏显示（后端 `@Sensitive` 已处理），查看明文需单独权限并记录日志；不写入任何状态管理或本地存储。
5. 密钥类配置（大模型 API Key、企业微信 Secret）：列表与详情只显示“已设置 / 未设置”；修改时用 `type="password" show-password`，留空表示不修改。
6. 选校引擎参数（权重、阈值）修改成功后提示“新参数只对之后的测评生效”。

## 7 交互约定

1. 删除、停用、生成或停用密钥、回滚、重投、修改运行参数等不可逆或影响线上的操作，必须二次确认。
2. 会调用大模型（产生费用）或给学生发消息（企业微信、小程序通知）的操作先提示再执行。
3. AI 生成内容在页面上必须标明“AI 生成，待审核 / 已审核”，未审核内容不能直接发给学生。
4. 下拉数据量可能较大时（院校、项目、顾问）用 `filterable` 并一次加载 `pageSize: 1000` 以内；超出需改为远程搜索。
5. 表格操作列 `class-name="small-padding fixed-width"`，按钮 `link type="primary"` + 图标。
6. 不在前端缓存敏感数据（学生个人信息、密钥）；关闭弹窗时清空。

## 8 构建与验证

1. 本地：`yarn dev`（代理 `/dev-api` → `http://localhost:8090`，后端 zt-abroad-parent 的 zt-admin）。
2. 提交前执行 `yarn build:prod`，不得有编译错误。
3. 页面联调：用后端真实接口逐项验证增删改查、权限按钮、字典显示与错误提示。
